# Accessibility — the procedure and the numbers

Read by `gui` (critique/audit) and by the engines when the domain is `gui`. The headline rules stay
in `context.md` (design every state, colour never carries meaning alone, visible affordances and
focus rings); this cell carries the verification procedure and the exact values. Alt-text wording is
`alt-text.md`. Adapted from `jakubkrehel/skills` `better-accessibility` (MIT).

**Most accessibility is free if you use the platform.** Native elements ship with keyboard support,
real labels announce themselves, and a visible focus ring is one CSS rule. When unsure, take the
platform default over a custom rebuild, and remove ARIA rather than add it.

## Reviewing means two walks

1. **Keyboard-only** — every flow completes without a mouse.
2. **Screen-reader** — every control announces a name, a role and its state.

Report every check you could not actually run as unverified, never as passed.

## Native elements first

The first rule of ARIA: don't use ARIA when a native element exists. `<button>` for actions,
`<a href>` for navigation, never `<div onClick>`. A real link supports Cmd/Ctrl/middle-click. **No
ARIA is better than bad ARIA.**

## Focus

- Style `:focus-visible`, not bare `:focus` — keyboard users get the ring, mouse users usually
  don't. Prefer the browser's unmodified indicator.
- A custom ring: at least a `2px` solid perimeter (or equivalent visible area), verified against
  every adjacent colour it crosses, `currentColor` included, and preserved in forced-colors mode.
  Never `outline: none` without a verified replacement.
- Modals: `inert` on the background, focus moved inside on open, returned to the trigger on close,
  `overscroll-behavior: contain` so the background doesn't scroll.

## Keyboard

Every pointer interaction needs a keyboard path, per the ARIA APG patterns: Escape closes overlays,
arrows move within composite widgets, Tab moves between widgets, Enter/Space activate. Only
`tabindex="0"` (join the tab order) and `tabindex="-1"` (programmatic focus) — positive values break
the order. Composite widgets use roving tabindex: the active item is `0`, every other `-1`.

## Hit areas

WCAG 2.5.8 AA floor is **24×24 CSS px**. Aim for **44×44 on touch**, **40×40 on desktop** where
density permits. Extend with a pseudo-element when the visible element should stay smaller; never
let extended areas overlap; give decorative layers `pointer-events: none` so a glow never swallows
the clicks meant for the control beneath it.

## Forms

- Every input gets a `<label for>` or wrapping `<label>`; a placeholder is never a label. Label and
  control share one hit target with no dead zone between a checkbox and its text.
- `autocomplete` with a meaningful `name`, plus the `type`/`inputmode` that summon the right
  keyboard. Never block paste — users paste passwords and one-time codes.
- Keep submit enabled until the request starts, then disable with a spinner and the original label.
  Validate on submit; mark failing fields `aria-invalid="true"`, point `aria-describedby` at the
  inline error, focus the first invalid field.
- Native `disabled` for genuinely unavailable; `aria-disabled="true"` only when it should stay
  focusable, with pointer/keyboard/form behavior blocked in code.

## Announcing dynamic content — three mechanisms, three jobs

| Mechanism | Carries |
| --- | --- |
| `aria-describedby` | Field-specific validation |
| `role="status"` (polite) | Non-urgent updates not tied to a control: toasts, result counts |
| `role="alert"` | Urgent untied errors, and nothing else |

Repeated polite announcements need a stable empty region rendered *before* its text updates.
Dynamically inserted alerts vary in screen-reader support — test on the ones you target.

## Reduced motion

Wrap motion in `@media (prefers-reduced-motion: no-preference)` so it is opt-in; under reduced
motion replace slides and scales with opacity crossfades and kill parallax and autoplay. Two rules
hold regardless of the preference: autoplaying media needs a visible pause control, and toasts
carrying an action or an error stay until dismissed.

## Structure and zoom

- Headings form a coherent outline: one `<h1>`, levels nested without skipping, one visible `<main>`,
  a "Skip to content" link first when chrome precedes it, `scroll-margin-top` on anchored headings.
- The page works at 200% zoom and reflows at 320px width without horizontal scrolling. `min-height`
  over fixed `height` on text containers; never cap zoom in the viewport meta.

## The mistakes that recur

| Mistake | Fix |
| --- | --- |
| Custom focus colour assumed to work everywhere | Verify against every adjacent colour and forced-colors mode |
| Repeated polite update inconsistently announced | Stable empty status region; update its text |
| `assertive` live region for a routine toast | `polite`; reserve `assertive` for errors |
| `aria-hidden="true"` on a focusable element | Remove it or make the element non-focusable |
| Submit disabled until the form is valid | Keep it enabled; validate on submit, focus the first error |
| Hover treatment stuck after a tap on touch | Gate hover styling with `@media (hover: hover)` |
| Tooltip on a natively `disabled` control | Text beside it, or `aria-disabled` so it stays focusable |
