# Writing documents agents read

A file map. Open the row that matches what you are doing; the knowledge is in the file, not
here.

| Open | When |
| --- | --- |
| [`../improve/POINTERS.md`](../improve/POINTERS.md) | Writing a skill `description`, a `SKILL.md` line naming a sibling, or a `CLAUDE.md` line naming a doc. Also before deciding to inline material because "nobody reads the doc" — sharpening the pointer comes first. |
| [`../improve/WRITING-SKILLS.md`](../improve/WRITING-SKILLS.md) | Authoring or restructuring a skill: invocation choice, the information hierarchy, when to split, pruning, leading words, the five failure modes. |
| [`../improve/SKILL-GLOSSARY.md`](../improve/SKILL-GLOSSARY.md) | A bolded term in `WRITING-SKILLS.md` whose full definition you need. |
| [`../improve/CLAUDE-MD.md`](../improve/CLAUDE-MD.md) | Rebuilding or triaging a `CLAUDE.md`: measuring it, reading its history, the six verdicts, building hooks before deleting prose. |

Judging a document that already exists, rather than writing one, is `improve` —
[`../improve/aspects/skills.md`](../improve/aspects/skills.md) for a skill,
[`../improve/aspects/claude-md.md`](../improve/aspects/claude-md.md) for a `CLAUDE.md`.
Judging whether a rule was obeyed across real sessions is `audit-session`.
