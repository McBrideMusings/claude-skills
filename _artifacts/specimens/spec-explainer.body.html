Mechanism

How the artifact tool assembles a hermetic file

One body fragment goes in; one self-contained HTML file comes out, with no network request in it.

After this you can add a widget, add a kind, or debug why a stylesheet did not land — without reading the whole 742-line tool.

The tool exists so the stylesheets never enter the model's context. The model writes content; tools/artifact:1 supplies the reset, the theme plumbing, the picker and the harness JS.

Input A body fragment: real HTML, no <head>, no reset, no theme block. It may carry its own <style> and <script>, which get hoisted.
Path build resolves the kind, concatenates _base.css with the kind stylesheet, appends each enabled widget's CSS and JS, then writes one file.
Gotcha A <script> cloned out of a <template> never executes. Axis listeners must sit at the top level of the fragment.
Fails A <link rel="stylesheet"> anywhere in the fragment breaks the hermetic guarantee and renders bare on a plane.
Normal case Exit code 0 and a file at --out. A non-zero exit means nothing was written at all.

The build, step by step

  1. Resolve the kind. Five are valid; an unknown one exits 2 before touching the filesystem.
  2. Collect the widget set. Kind defaults, then --with, then --without, in that order.
  3. Read the old file when --round N is set, keeping every round that is not N.
  4. Write once. One open() call, one file, no temp directory.

Two pickers, two jobs

switch

One variant at a time at full size. The rail holds round, variant, axes and device.

Use when the question is which direction.

list

Every variant stacked, one per screenful, each captioned.

Use when the answer is going to be read scrolling, not clicked.

# one output file for the whole life of a topic
artifact build --kind prototype --picker switch --round 2 \
  --title "Branches Pane" \
  --out "$ROOT/tmp/claude/prototypes/branches-pane/branches-pane.html"  ← same path every round
Why rounds live in the output file rather than a sidecar

A sidecar is a second thing to keep in sync and a second thing to lose. The built file already contains every round's templates, so the file is its own history and copying it copies everything.
